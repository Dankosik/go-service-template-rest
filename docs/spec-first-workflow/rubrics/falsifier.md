# Falsifier

Load for each non-obvious proof obligation.

Name the plausible wrong observable behavior, control setup and action or fault
trigger, derive the expected result from authority independent of the production
path, and choose the narrowest complementary proof boundary. The oracle must
change verdict when the named wrong behavior occurs. Source text, file presence,
compilation, lint, coverage, and a green suite prove only their direct structural
claim unless the accepted contract is itself structural.

Use domain methods only for triggered pressure: `go-test-strategy` for Go proof
selection, `go-performance` plus Benchmarking for workload/budget claims, and
the accepted security, money, retry/replay, concurrency, data/migration, or
release owner for its controlled actor/state/order/time boundary. A wider proof
level must observe something the narrower level cannot; it does not duplicate
the same oracle.

A required unavailable input blocks its claim and reopens the smallest owner.
Missing test or fixture code is a proof gap, not fail-before behavioral evidence.
