# Goose migration runtime test plan

status: ready

Each scenario has an independent observable that fails for a plausible wrong
implementation. Test fixtures belong to implementation; production Down
remains unavailable.

| ID | Source / risk | Disposition and falsifier | Controlled setup, action, and independent oracle | Boundary and command | Owner / reopen |
| --- | --- | --- | --- | --- | --- |
| TD-1 | Source grammar and parser admission | Script and Go table tests; a wrong implementation accepts legacy pairs, nested or noncanonical SQL, duplicate versions, repeated/missing directions, environment substitution, or `NO TRANSACTION`, or opens PostgreSQL before rejecting them. | Build isolated source trees for every negative and for canonical one-file Up/Down sources; use a database-open spy in Go. Oracle is the distinct source failure plus zero opens; the repository gate additionally invokes the pinned Goose parser. | `go test -vet=off ./internal/infra/postgresmigrate -run Source`; `make migration-source-check`. | `postgresmigrate/source.go` and source gate; reopen Source Design if the grammar changes. |
| TD-2 | Configuration and deadline reserve | Config/unit matrix; a wrong implementation accepts nonpositive timeouts, lets lock timeout reach overall timeout, loses the cleanup reserve, or omits pgx server-side limits. | Load defaults, boundary values, malformed durations, `lock >= total`, and a valid custom set; inspect the pgx config passed to the connector. Oracle is pre-connect rejection or exact connect/statement/idle-transaction/lock budgets and one reserved cleanup window. | `go test -vet=off ./internal/config ./internal/infra/postgresmigrate -run '(Config|Budget|Connection)'`. | Config and connection adapter; reopen Reliability Design if the budget model changes. |
| TD-3 | Applied/source prefix integrity | Unit matrix plus real PostgreSQL corruption cases; a wrong implementation trusts max version alone, accepts duplicates/gaps/out-of-order rows, or accepts database-only history. | Feed newest-first Goose rows with absent table, bootstrap-only, valid prefixes, non-prefixes, duplicates, unapplied rows, bad bootstrap placement, and source-behind state; independently mutate a disposable `goose_db_version`. Oracle is exact accepted prefix or fail-before-SQL state error. | `go test -vet=off ./internal/infra/postgresmigrate -run '(Prefix|State)'`; integration-tag prefix cases. | `postgresmigrate/state.go`; reopen Data Design if the store contract changes. |
| TD-4 | Transactional execution and partial result | Real PostgreSQL lifecycle tests; a wrong implementation leaves failed DDL committed, hides completed migrations, or reruns an already-current source. | Run a successful migration, a later transactionally failing migration, then a repaired source; also run Up twice and test Down/Up through the test-only adapter. Oracle is schema/catalog state, Goose version rows, ordered per-file results, rollback of the failing file, and explicit no-change. | `go test -count=1 -tags=integration ./test/... -run 'PostgresMigrate.*(Up|Rollback|Partial|Down)'`. | Migration adapter and integration fixture; reopen Execution Design if transactional policy changes. |
| TD-5 | Dedicated session lock and concurrency | Real contention and race proof; a wrong implementation performs preflight outside the lock, allows duplicate execution, or shares the application pool. | Hold the Goose advisory lock on one dedicated session; start two migrators and release deterministically. Oracle is configured timeout or serialization followed by no-change, exactly one schema effect, and independent connection ownership. | Integration lock cases; `go test -vet=off -race ./internal/infra/postgresmigrate`. | Connection/lifecycle adapter; reopen Concurrency Design if lock identity changes. |
| TD-6 | Timeout, cancellation, and bounded cleanup | Real PostgreSQL timeout/cancel cases plus lifecycle unit tests; a wrong implementation starts later SQL, hangs in unlock, or loses a cleanup error. | Block DDL, run `pg_sleep`, cancel after an owned event, and inject a locker whose unlock stalls/fails. Oracle is SQLSTATE/context class, no later migration effect, unlock attempted with detached bounded context, total return within total plus one cleanup budget, and both operation and cleanup failures retained. | Focused unit plus integration `PostgresMigrate.*(Timeout|Cancel|Cleanup)`. | Migration lifecycle; reopen Reliability Design if cleanup semantics change. |
| TD-7 | Production command and safe observability | Command tests and built-binary process proof; a wrong implementation accepts arguments, exposes Down, logs DSN/SQL/provider text, omits partial safe results, or starts application migration. | Invoke no-arg, unexpected-arg, missing-source, invalid-config, no-change, success, contention, and SQL failure cases with secret canaries in DSN and SQL. Oracle is stable exit class and JSON fields with no canary; service binary import/process proof shows no migration call. | `go test -vet=off ./cmd/migrate ./cmd/service/...`; integration process cases. | `cmd/migrate`; reopen Operator Contract if the command surface changes. |
| TD-8 | Actual-source and production-image rehearsal | Aggregate integration; a wrong implementation tests only synthetic fixtures, packages the wrong source, or declares readiness before migration. | With absent repository corpus, require an existing empty image directory and database-state check. With a canonical fixture corpus, run host Up/no-op/Down/Up, one built runtime image `/migrate`, then the same image's readiness and bounded SIGTERM. Oracle is equal target version, image source identity, readiness, and clean exit. | `make migration-validate`. | Integration harness and Docker image; reopen Delivery Design if image topology changes. |
| TD-9 | Git review-history scopes | Script self-tests; a wrong implementation guesses a base, normalizes push history through merge-base, or accepts modification/rename/copy/deletion of prior files. | Temporary repositories cover worktree, PR merge-base, exact push base, all-zero empty tree, invalid refs, squash/merge/force-push shapes, and new-file evolution inside one boundary. Oracle is reported scope plus additions-only result. | `make migration-history-check`; script self-test target. | Git history gate; reopen History Design if CI events change. |
| TD-10 | Durable OCI publication history | Pure corpus/API decision self-tests plus workflow static checks; a wrong implementation bootstraps over a prior package, trusts `404`, changes/removes prior bytes, lets main/release race, or promotes a public alias first. | Directory/image fixtures cover canonical additions, byte change, rename/deletion, empty corpus, marker half-state, branch recreation, existing/absent package, incomplete pagination, unauthorized responses, exact/mismatched bootstrap SHA, and marker-before-alias order. Oracle is fail-closed decision or identical resolved candidate/marker/public digests. | `make migration-publication-check`; `make actionlint`; workflow self-test fixtures. | Publication guard and `cd.yml`; reopen Publication Design if registry/channel ownership changes. |
| TD-11 | sqlc canonical source | Generation/drift proof; a wrong implementation reads Down SQL, legacy globs, or stale generated output. | Point sqlc at the canonical directory with a fixture whose Down section would conflict if consumed; regenerate from Goose Up sections. Oracle is successful generation and byte-clean drift. | `make sqlc-check`. | `internal/infra/postgres/sqlc.yaml`; reopen Data Tooling if sqlc migration parsing changes. |
| TD-12 | Template profile purity | Initialization contract tests; a wrong implementation leaves Goose runtime/tooling/source/docs in `DATABASE=none`, removes them from PostgreSQL, or is non-idempotent. | Initialize clean copies with database disabled and enabled, repeat initialization, inspect module graphs, owned files/commands/docs, then run each retained profile's focused checks. Oracle is exact owner presence/absence and byte stability. | `make template-init-check`. | Init script and fixture; reopen Template Ownership if profiles change. |
| TD-13 | Replacement completeness and aggregate health | Negative dependency/text scans plus repository gates; a wrong implementation retains `golang-migrate`, paired-source/dirty-force instructions, stale generated state, or breaks unrelated REST/runtime behavior. | Search production/tests/tools/docs for retired module and concepts with narrow allowed historical spec exceptions; run module drift, focused/race/integration, delivery, and repository aggregate serially. Oracle is no live legacy owner and all matching gates green. | `make mod-tidy-check`; `make check`; `make delivery-quality`; `git diff --check`. | Bounded final candidate; reopen the narrow owner named by a failing gate. |

Live GHCR publication and Railway deployment remain outside local proof because
they are externally visible writes. Repository readiness requires all local and
simulated publication checks plus documented platform inputs. A future live
rollout claim requires an authorized publication, verified marker and channel
digests, successful Railway pre-deploy `/migrate`, and application readiness
from that same digest.
