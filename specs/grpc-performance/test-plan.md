# gRPC performance evidence test plan

status: ready

The current implementation host has no Docker-compatible runtime or k6
binary. The matrix therefore keeps Phase A implementation proof and the
mandatory Phase B activation proof separate. An unavailable Phase B command is
a blocked input, not a passing or waived result.

- PERF-1 maps to TD-3 and TD-4.
- PERF-2 and the public four-cardinality harness boundary map to TD-5 and TD-8.
- PERF-3 maps to TD-2 and TD-8.
- PERF-4 and PERF-5 map to TD-8 and TD-9.

- PERF-7 maps to TD-4.
- PERF-8 and preserved runtime/generated behavior map to TD-1, TD-2, TD-5,
  TD-6, and TD-7.
- Performance, generated-contract, lifecycle/cleanup, compatibility, failure,
  and rollout/claim lenses are covered above. Retry/replay, persistence,
  migration, security identity, money, and deployment transitions are
  untriggered because the accepted capability is local, benchmark-only,
  stateless, reflection-free, and changes neither runtime credentials nor a
  deployed route.

Phase A can proceed because every Phase A obligation has an available carrier.
TD-8 and TD-9 are mandatory only for the separately accepted Phase B claim and
remain blocked on the named external runtime input.
