# gRPC runtime optimization test plan

status: ready

| ID | Claim and plausible wrong behavior | Controlled falsifier and oracle | Proof boundary and command | Owner / reopen |
| --- | --- | --- | --- | --- |
| TD-1 | OPT-1; sampling could hide errors/slow calls, log health, vary for one ID, or still do work with INFO disabled. | Invoke unary and stream interceptors with fixed request IDs, OK/error results, threshold boundaries, health names, and enabled/disabled handlers. Assert exact record count/status and handler completion; pure sampler boundaries are deterministic. | Package tests: `go test -vet=off ./internal/infra/grpc -run '^(TestAccessLog|TestNewServerRejectsUnboundedConfig)'`. | `internal/infra/grpc`; failures reopen D1. |
| TD-2 | Config could accept invalid rates/durations or map defaults incorrectly. | Load defaults and environment boundary/invalid values; assert `[0,1]`, finite rate, non-negative duration, and exact bootstrap mapping through the runtime constructor. | `go test -vet=off ./internal/config ./cmd/service/internal/bootstrap -run 'GRPC'`. | config/bootstrap; failures reopen Specification or D1. |
| TD-3 | Health filtering could disable health itself, client spans, or business telemetry, or fail to restore opt-in. | Call real health and registered business methods through `grpcx.NewServer` with SDK recorders. Assert health response unchanged; default has no server health signal, business signal exists, opt-in restores server health; unknown remains absent. | `go test -vet=off ./internal/infra/grpc -run '^(TestOTel|TestServerObservability|TestStreamingPolicy)'`. | `internal/infra/grpc`; failures reopen D2. |
| TD-4 | The optimization could merely move cost or break correctness. | Repeat the same production-composed 64B workload for full JSON, sampled-out success, and level-disabled variants; keep exact payload oracle and report time/bytes/allocs. Isolate the interceptor policy with the same handler and JSON sink so full, sampled-out, level-disabled, and health-excluded paths can be distinguished when transport variance is larger than the fixed cost. Compare equivalent evidence with `benchstat`; do not impose a numeric pass budget. | `go test -vet=off -run='^$' -bench='^BenchmarkGRPCUnary/(full_log_disabled|full_success_unsampled|full_json)/64B$' -benchmem -benchtime=500ms -count=10 ./internal/infra/grpc`; `go test -vet=off -run='^$' -bench='^BenchmarkGRPCAccessLog$' -benchmem -benchtime=500ms -count=10 ./internal/infra/grpc`; then repository bench comparison. | performance owner; regressions reopen D1, noisy end-to-end results narrow the claim to the isolated fixed-cost boundary. |
| TD-5 | PGO activation could silently use an absent/generic profile or make rollback fail. | Build with default `off`; call `build-pgo` with empty, missing, and malformed inputs and require non-zero exit; validate one actual CPU profile and require successful service build. | `make build`; focused Make invocations from a shell test/procedure; `docker build -f build/docker/Dockerfile .` or existing image gate. | Make/Docker delivery owner; failures reopen D3. |
| TD-6 | Config/docs/profile extraction or unrelated gRPC behavior could drift. | Run initialized gRPC profile twice, focused gRPC/config/bootstrap suites, Dockerfile/static delivery checks, and whitespace proof. | `TEMPLATE_INIT_PROFILE=grpc make template-init-check`; `go test -vet=off ./internal/infra/grpc ./internal/config ./cmd/service/internal/bootstrap`; `make dockerfile-check`; `git diff --check`. | repository closeout; failures reopen the owning task. |

Performance coverage is TD-4; observability and failure precedence are TD-1
through TD-3; delivery/rollback is TD-5; compatibility/profile purity is TD-6.
Security, persistence, money, retry/replay, generated contracts, and
cross-service rollout are untriggered because no credential, data, RPC schema,
retry policy, or deployed neighbor changes.
