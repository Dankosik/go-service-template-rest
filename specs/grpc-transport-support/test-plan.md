# gRPC capability test plan

status: ready

Each row names an observable that would fail for a plausible wrong
implementation. Test code and fixtures belong to implementation.

| TD-8 | SRV-4 status disclosure | Table/unit plus handler integration; wrong implementation passes raw handler/dependency or policy errors, sanitizes service-owned auth policy status, breaks standard health status, or maps local overload to `UNAVAILABLE`. | Inject context errors, each `problem.Code`, raw secret-bearing handler and unary/stream policy errors, an unmarked handler `status.Error`, panic, process saturation, direct unary/stream policy statuses, and unknown health service. | TD-9 | SRV-5 correlation and telemetry | Unary/stream interceptor and `StatsHandler` tests; wrong implementation accepts invalid request IDs, omits response metadata, breaks trace propagation, omits streaming telemetry, logs payloads, reports a pre-sanitization status, or labels metrics from peer input. | Send valid, absent, oversized, and invalid IDs; exercise registered unary/stream methods, raw handler and policy errors, panic recovery, health traffic, and arbitrary unknown method paths with explicit client/server tracer and meter providers plus JSON log capture and secret canaries. | TD-10 | SRV-6 finite bounds | Config, application-admission, and transport boundary tests; wrong implementation treats zero as unlimited, admits oversized work, overflows bootstrap transport conversions, or falsely promises an RPC status for a pre-RPC rejection. | Table invalid bounds and direct bootstrap values above `uint32`; send over-limit metadata and receive/send messages; saturate process semaphore while health remains callable; exhaust the connection cap separately. Public Railway ingress is deliberately outside the local completion claim. Its
proof input is a live Railway project and public domain, neither authorized by
this task. Before any future public-support claim, Delivery must run a fresh
unary plus streaming trailer probe through the exact deployed public route, or
prove the TCP Proxy plus application-TLS route. Private-network guidance is a
documented topology constraint, not local end-to-end deployment proof.
