## Proof-boundary decisions

- Standard-library unit tests own immutable definition construction, closed
  acceptance/result vocabularies, strict typed decoding, pure transition policy,
  deterministic jitter, and config parity. PostgreSQL would add no observable to
  those claims.
- `testing/synctest` plus owned Store-stage gates owns coordinator cadence,
  renewal priority, cancellation, claim handoff, rescue bounds, observation, and
  drain ordering. Wall-clock sleeps are rejected for those paths.
- PostgreSQL 17 through the existing digest-pinned `pgtest` family owns schema,
  writer authority, unique identities, transaction visibility, row locks,
  `SKIP LOCKED`, claim-time revision coverage, leases, fencing, pause, and durable
  state. A fake Store or SQL expectation cannot prove those claims.
- Unix subprocesses own `/jobs-worker` readiness, SIGTERM, non-cooperative hard
  exit, broken control-Session terminalization, fresh-process replacement, and
  two-worker recovery. In-process close/reopen is not replacement proof.
- Generated disposable checkouts own profile omission/retention, double
  initialization, sibling independence, exact runtime entrypoints, and module
  closure. Source markers alone are not deletion proof.
- One synthetic admitted definition supplies decision-neutral small identities,
  policy budgets, strict payloads, and a test-only same-database effect ledger.
  Those values prove the generic mechanism only; they are not defaults or
  adopter readiness evidence.
- Operator mutation, multi-class/fairness, periodic scheduling, destructive
  contraction, and production capacity remain disabled at their named adopter
  checkpoints. Current proof establishes fail-closed absence; their later
  behavior uses the fixed future carrier or target procedure in **TD-JOBS-021**.
- Commands naming new tests are post-implementation commands. The current absence
  of their code is a proof gap, not behavioral fail-before evidence.

## Deterministic controls and fixtures

- **F-JOBS-1 — canonical definitions.** `email.v1` is a complete baseline
  definition with strict required fields, executable retry/recovery/
  ambiguous-effect/duration policy, and a deterministic SHA-256 intent vector.
  `email.v2` is a forward-shipped compatible revision. `email.v3` is the
  deliberately unknown revision. Tests remove exactly one B4 slot at a time;
  no library or test helper fills it.
- **F-JOBS-2 — durable effect.** An integration-only table keyed by the business-
  effect identity records one conditional effect and its attempt facts. It is
  created only in isolated test databases, never in canonical migrations. Its
  independent writer readback distinguishes no effect, one effect, and conflicting
  intent across crashes and overlaps.
- **F-JOBS-3 — PostgreSQL schedules.** Concurrent stages synchronize on backend
  PID, `pg_stat_activity`, `pg_blocking_pids`, `pg_locks`, committed rows, and
  owned channels. Test-only RLS/trigger blockers on isolated databases force
  statement work; explicit relation/row locks force lock waits. Elapsed time is
  only an outer hang diagnostic.
- **F-JOBS-4 — claim/revision linearization.** One transaction commits an unknown
  revision before a claim snapshot; another holds it uncommitted until after the
  claim statement. The first permits no claim. The second may linearize after
  that claim, but the next claim must close admission. Pause/claim tests force
  both lock orders on the neutral scope row.
- **F-JOBS-5 — operation budgets.** A shorter caller context proves client
  cancellation. Test-only server blockers separately exceed transaction-local
  `statement_timeout`, while held locks exceed `lock_timeout`, for claim,
  renew/cancel observation, finalize, rescue read/write, and observation. The
  test-owned `ACCESS EXCLUSIVE` lock is rolled back and its connection released
  before an independent state read. A test-owned in-transaction probe reads both
  local timer settings: for each admitted effective budget it must observe the
  exact accepted 10ms (10%-capped) reduction while the child retains the full
  Store budget. Cancellation still returns the caller error, and otherwise
  SQLSTATE, durable state, and backend disappearance—not elapsed time—classify
  the owner.
- **F-JOBS-6 — coordinator time.** Under `testing/synctest`, let operation budget
  be `T` and lease be `6T`. A non-renewal stage starts immediately before lease/3
  (`2T` after the last successful claim or renewal) and consumes `T`; renewal
  must run next and complete or cancel ownership within `2T` of that competing-
  stage start, no later than `4T` after the last successful claim or renewal and
  before lease expiry. Every competing stage records invocation order.
- **F-JOBS-7 — process artifacts.** The fixed integration fixture copies an
  initialized checkout and injects only a test-owned binary-local registry
  builder. It builds and hashes three `/jobs-worker` binaries: prior old-only
  (`v1`), mandatory expand/rollback N-1 (`v1+v2`), and N (`v1+v2`, producer may
  emit `v2`). Tests restart the exact hashed N-1 artifact; they never mutate a
  running registry or substitute an in-process bootstrap.
- **F-JOBS-8 — process control.** Health endpoints, durable job/attempt rows,
  backend PID, and child exit are owned events. SIGTERM or `pg_terminate_backend`
  is sent only after the expected event. Every child is joined and every acquired
  database/container resource is registered for cleanup before the fault. For
  TD-JOBS-017 only, the existing `jobs_test_worker` build adds one
  bootstrap-package, test-only unsafe-drain marker writer selected by an
  environment-named fixture file. `runLifecycle` invokes it exactly once after
  `StartDrain` returns an unsafe result and before any coordinator or diagnostics
  cleanup branch. The same test-only writer records a distinct prohibited-cleanup
  marker immediately before any post-unsafe coordinator or diagnostics join call;
  the carrier requires that marker to remain absent. The normal build has no
  marker implementation or runtime switch; these are observables at the existing
  lifecycle boundary, not fault injection or a second drain owner.
- **F-JOBS-9 — one-off time.** `available_at` and observations come from the
  writer's `clock_timestamp()`. A future row is proven ineligible, all workers
  remain down across that writer instant, and recovery polls only after the writer
  reports the instant crossed. Polling time is an outer diagnostic, not the
  eligibility oracle.
- **F-JOBS-10 — telemetry.** A manual OTel reader scrapes twice while a recording
  Store counter remains unchanged; only an explicit observation refresh may
  change the cached gauges. Unique payload/identity/error sentinels must not occur
  in metric labels or exported series.
