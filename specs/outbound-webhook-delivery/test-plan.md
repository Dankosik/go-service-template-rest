## Proof-boundary decisions

- PostgreSQL 17 through the existing digest-pinned `pgtest` harness owns every
  transaction, writer-readback, clock-high-water, bounded fairness-page,
  capacity-slot, fence, redrive, retention, privacy, and cross-replica claim.
  Mocks may check local call order but cannot satisfy those claims.
- Standard-library controlled DNS, TCP, TLS, and receiver peers own whole-answer
  SSRF denial, rebinding, actual-dial checks, signature bytes, one-send behavior,
  stage bounds, and remote-effect ambiguity. Parser or fake-transport success is
  not network proof.
- A separately started `/webhook-worker` process owns startup, cached readiness,
  PostgreSQL loss/recovery, SIGTERM drain, SIGKILL/restart, join, and exact-image
  lifecycle. In-process cancellation is complementary only.
- Canonical acceptance, operator-action, HMAC, signature-evidence, and DNS-set
  vectors are reproduced from the reviewed design values, never regenerated
  from production output. A mismatch fails before database or network proof.
- The engine ceilings are structural safety bounds, not throughput defaults.
  Local real-PostgreSQL tests prove bounded work and arbitration; Gate 1 alone
  owns the adopter workload, p95/p99, WAL, vacuum, pool, lock-wait, and recovery
  budget that can support a capacity or production claim.
- Local migration/profile/image checks prove repository wiring only. Gates 2-6
  separately require exact target image, writer, receiver, egress, secret,
  replica, retention, and owner evidence. No component-health result closes a
  rollout gate.
- Every named command is a required current-candidate check. A missing test,
  skipped carrier, or narrower oracle is a proof gap, not a passing result.

## Deterministic controls

- Database schedules synchronize on committed rows, backend identity,
  `pg_stat_activity`, `pg_blocking_pids`, row/table/advisory locks, capacity-slot
  ownership, and test-owned transaction gates. Elapsed time is only an outer
  hang diagnostic.
- Clock cases lock `webhook_clock` before forcing server samples on independently
  controlled sessions. Writer readback, not a Go clock, decides high-water,
  regression, deadlines, and recovery.
- Fairness cases seed exact candidate order and page size, lock or saturate named
  candidates, and inspect committed `last_considered_sequence` values after each
  page. Poll cadence is driven by an owned event; no sleep decides selection.
- Network cases use a test-owned resolver that can return ordered A/AAAA sets and
  change answers at an owned event, a TLS peer with controlled hostname/cert,
  and a receiver that records exact request bytes before returning, stalling, or
  dropping the connection. Request count and durable attempt rows are independent
  one-send/ambiguity oracles.
- Crash recovery seeds exact pre-send and authorized-send PostgreSQL evidence,
  independently reads it, expires the lease, and starts the exact image as a
  fresh process. Controlled receiver loss remains a separate network oracle;
  the target receiver/recovery path remains TD-WH-033/034.
- Privacy and retention cases derive all horizons from PostgreSQL UTC, force both
  serial orders with row locks, inventory every dependent relation from an
  independent writer connection, and resume bounded batches after interruption.
- Disclosure cases inject unique payload, URL, owner, address, key-reference,
  secret, raw-signature, response, header, SQL, and remote-error sentinels, then
  inspect rows, diagnostics, logs, spans, metric points/labels, and receiver
  headers.
