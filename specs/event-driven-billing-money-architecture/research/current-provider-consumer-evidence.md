## Billing-Service Current Surface

- `billing-service` OpenAPI currently has global `security: []` and exposes only `/api/v1/ping`, `/health/live`, `/health/ready`, and `/metrics`; there is no current reserve, finalize, write-off, account-effect, operation-readback, inbox, or outbox API in the published service contract (`api/openapi/service.yaml:11`, `api/openapi/service.yaml:17`, `api/openapi/service.yaml:91`).
- Repo architecture says the shipped endpoints are intentionally small, and any new business endpoint must choose public-by-design, real OpenAPI security plus auth middleware and 401/403 Problem responses, or blocked pending a security spec (`docs/repo-architecture.md:92`).
- The repository does not ship an always-on background worker runtime; async work needs explicit business package, infra adapter, lifecycle/config/telemetry/shutdown ownership, and usually a distinct binary when the lifecycle or scaling model differs from HTTP (`docs/repo-architecture.md:110`, `docs/repo-architecture.md:119`).

## Product And Money Constraints To Carry Forward

- Before paid inference, proxy should ask billing to reserve; reserve must be idempotent and fail closed when funds, account state, or policy do not allow the charge (`docs/PRD.md:72`, `docs/PRD.md:74`).
- Finalization releases unused hold, commits charge, records ledger effect, and returns a replay-stable outcome; write-off/reversal are explicit ledger effects, not silent balance edits (`docs/PRD.md:78`, `docs/PRD.md:84`).
- Billing exposes synchronous internal HTTP for request-path money gates and async workers for stale reservation repair, delayed evidence retry, reconciliation jobs, treasury/admin workflows, and support-safe backfills (`docs/PRD.md:114`, `docs/PRD.md:116`, `docs/PRD.md:118`).
- Billing fail-closed behavior is required for paid usage/top-up creation when billing is unavailable; ambiguous timeout retry must reuse the same operation identity or reconcile first (`docs/PRD.md:120`).
- Required invariants forbid Redis or in-process TTL caches as the money correctness store and forbid raw prompts, outputs, SSE chunks, payment secrets, bearer tokens, API keys, DSNs, or full webhook bodies in logs/traces (`docs/PRD.md:122`, `docs/PRD.md:129`, `docs/PRD.md:134`).
- Final charge is capped by the authorized reserve; excess after external effect becomes explicit write-off, compensation, or reconciliation, not retroactive overcharge (`docs/critical-billing-context.md:110`, `docs/critical-billing-context.md:116`).
- Hot-path posture expects O(1) money operations, one short Postgres transaction, an account-balance row lock or equivalent single-writer invariant, no outbound HTTP while holding the transaction, unique indexes for replay-critical identities, and low-cardinality metrics (`docs/critical-billing-context.md:175`, `docs/critical-billing-context.md:181`).
