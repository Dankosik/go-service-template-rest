# Test design: idempotent PostgreSQL inbox consumption

status: ready

Authority: [`spec.md`](spec.md), [`design/overview.md`](design/overview.md), and
[`rollout.md`](rollout.md). The inbox remains a sibling pack: it proves a
same-PostgreSQL claim/effect and never becomes outbox state, NATS persistence,
or a generic consumer-ordering mechanism.

## Deterministic controls

- Every claim/effect oracle reads committed rows from the real PostgreSQL
  fixture. A mock transaction or recorded method call is insufficient.
- Concurrent claim tests use two real transactions and identify the losing
  backend's PostgreSQL lock wait before releasing the winner; elapsed time is
  only an outer diagnostic.
- NATS identity proof varies logical and publication identity independently and
  reads JetStream ACK/DLQ state plus PostgreSQL claim/effect state.
- Profile proof initializes isolated generated checkouts, reruns initialization,
  and compares the whole generated tree for zero drift.
- Commands naming new tests are post-implementation commands. A current
  `no tests to run` result is a proof gap, not a pass; the named scenario and
  oracle must exist before its command can be accepted.

## Bidirectional closure

| Accepted surface | Final disposition |
| --- | --- |
| R1 atomic apply/skip/failure/crash/commit-unknown outcomes and per-consumer scope | TD-INBOX-002 and TD-INBOX-003 |
| R2 logical identity, validation, ordinary redelivery, DLQ/redrive | TD-INBOX-001 and TD-INBOX-006 |
| R3 concurrent commit/rollback resolution and bounded wait | TD-INBOX-004 |
| R4 permanent recognition/no cleanup | TD-INBOX-005 |
| R5-R6 boundary and legal adapter placement | TD-INBOX-007 |
| R7 independent selection/removal and SQL/migration/generated authority | TD-INBOX-008 |
| Closed telemetry, existing retry/DLQ/drain behavior, no generic consumer ordering | TD-INBOX-009 |
| Rollout Gates 1-4, including consumer-before-relay | TD-INBOX-010 through TD-INBOX-012, with Gate 2 also using TD-INBOX-008 |

No row claims exactly-once delivery, covers an effect outside the claim
transaction, adds transport-owned PostgreSQL state, expires a claim, or
serializes generic consumer handling.
