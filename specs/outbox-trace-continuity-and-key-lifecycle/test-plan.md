# Test design: outbox trace continuity and ordering-key lifecycle

status: ready

Authority: [`spec.md`](spec.md) and [`design/overview.md`](design/overview.md).
The later ready production-closure design supersedes only the earlier
message-ID telemetry choice: W3C creation continuity remains, while event IDs
and ordering keys stay out of spans, metrics, and logs.

## Deterministic controls

- Real durable-state claims use the shared PostgreSQL integration harness and
  authoritative row/state-observation reads; mocks do not prove transaction or
  lock behavior.
- Trace claims use an installed span recorder and compare `TraceID`, link,
  parent, kind, status, and bounded attributes. Span presence alone is not the
  oracle.
- Concurrency tests hold the real ordering-head row lock and release it through
  owned channels or transaction commits. Wall-clock sleeps are outer failure
  diagnostics only.
- SQL and migration source remain canonical. Generated SQLC output is checked,
  never hand-authored.
- Commands naming new tests are post-implementation commands. A current
  `no tests to run` result is a proof gap, not a pass; the named scenario and
  oracle must exist before its command can be accepted.

## Bidirectional closure

| Accepted surface | Final disposition |
| --- | --- |
| R1 capture, absence/degradation, metadata exactness, separate allowance | TD-TRACE-001 |
| R2 linked publication, repetition, failure class, sampling/privacy | TD-TRACE-002 and TD-TRACE-003 |
| R3 adapter-visible creation context | TD-TRACE-004 / TD-OUTBOX-003 |
| R4 retirement table, observation, idempotence, restarted sequence, concurrency | TD-TRACE-005 and TD-TRACE-006 |
| R5 scope-exit placement and all preserved ordering, lease, drain, vocabulary behavior | TD-TRACE-008 |
| SQL/migration/generated authority | TD-TRACE-007 |

No scenario asserts exactly-once delivery, a tenant column, automatic key
retirement, or generic consumer ordering. Those remain explicit exclusions.
