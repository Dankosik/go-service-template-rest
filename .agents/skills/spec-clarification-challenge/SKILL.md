# Spec Clarification Challenge

Use for one concrete question that can change spec readiness. Do not use as a universal pre-review gate or a broad checklist.

Inspect the candidate decision, relevant evidence, assumptions, and non-goals. Try to expose a hidden scope change, missing invariant, ownership/source-of-truth conflict, unsupported compatibility/risk decision, or impossible proof path.

Return the strongest finding, evidence, why it changes or does not change readiness, and one disposition: repair spec, research, user/specialist decision, bounded proof/risk, or no action. Do not edit or approve the spec.
